# Response to the 2026-09-26 code, architecture and reliability review

The review ([2026-09-26-system-review.md](2026-09-26-system-review.md)) was made at `e607bc4`.
This maps each finding to the change, the test that now pins the corrected behaviour, and what
is still open. The review's probe scripts (`robustness-probes.ts`, `rpc-probes.ts`,
`oracle-boundary-probe.ts`) assert the defects as they were; they are kept as historical
evidence and now fail at their "defect present" assertions, which is the point.

Test counts after the changes: 26 Rust unit tests, 80 TypeScript tests (LiteSVM with the real
Meteora programs, plus mocked-transport off-chain tests). CI runs all of it and fails on SBF
build diagnostics.

## Architecture and contract items

- **Funding.** A maker can only accept when the fee vault holds `fee_per_period × duration`
  (checked multiplication at creation and acceptance). The draft page refuses an underfunded
  budget and the accept panel explains why. Test: "a maker cannot accept an agreement whose fee
  vault doesn't cover the term".
- **Grace and duration.** `start_ts` is now acceptance + 60 s: the setup window is separate from
  the term, so a one-period agreement can still be scored and paid.
- **Unobserved periods.** Kept as they were (neither pay, fail, nor reset the count) and stated
  precisely everywhere: "failed periods with no passing period between them".
- **Measurement promise.** The depth window is whole bins that never extend past
  `depth_window_bps` (the old ask side counted one extra bin); creation requires the window to
  be at least one bin step. The preview no longer calls the reference speed a replenishment
  deadline.
- **Optional analytics.** An unreadable reference pool no longer fails a check; the deviation
  is recorded as unknown.
- **Token risks.** The preview states a base mint's remaining mint authority and a quote mint's
  freeze authority as risks the bond doesn't cover.
- **Transaction delivery.** Keepers sign once, re-send the same bytes, look the signature up in
  history after expiry and raise `UnknownOutcome` for non-idempotent actions instead of
  rebuilding (tested with a mocked connection). App actions re-read the mandate through a
  cache-bypassing path before building, confirm against the blockhash's validity, and report an
  unknown outcome with the link rather than a failure to retry.
- **Build.** The SBF stack warnings came from `blake3 1.8 → digest 0.11 → hybrid-array`,
  pulled in by `solana-program` but never called. Pinning `blake3 = 1.5.5` in `Cargo.lock`
  removes them and the unknown-syscall warning; CI fails if either returns.
- **Jev.** Pinned to `jev-1.13.0`; the unused next-check question is gone; "leaving on purpose"
  became an observable outcome (no restoring placement within two periods), asked only while
  failing and abstaining on incomplete history; "drained by trading" (impossible for the
  committed measure) became "reference moved". The evaluation reports Brier scores,
  reliability bins and abstention, and says it is synthetic.
- **Ratings.** Presented as service history with a counterparty count; the model reads it with
  the same caveat. Money totals come from mandates per quote mint, not the profile's mixed sums.

## Still open

- **Deploying the program.** These are program changes; devnet still runs the reviewed build
  until it is upgraded. The account layout is unchanged, so existing accounts keep working. An
  open offer whose fee budget doesn't cover its term can no longer be accepted.
- **A real job store.** The watchtower's state is a JSON file per process: restarts resume, but
  several keepers or a real-value pilot need a database with leases.
- **Multi-keeper races and adversarial event volume** are not tested beyond the idempotent
  finalize and single-writer paths.
- **Per-mint profile aggregates on chain.** `MakerProfile` still sums raw amounts across quote
  mints; the app no longer uses those sums for money. Versioning the profile is deferred.
- **Supported-asset policy.** Quote mints aren't restricted on chain (USDC has a freeze
  authority); the risk is disclosed instead.
- **Release process** for mainnet: see [../release.md](../release.md).
- **Real-world model validation** needs frozen, chronological data from real agreements.
